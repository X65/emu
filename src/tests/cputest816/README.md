# 65816 instruction test ROM

`../cputest816.bin` is gilyon's 65816 test suite built to run headless under
`cpuemu`. 1610 tests, 847 of them in emulation mode, covering every opcode
except STP and WAI in every addressing mode, in 8- and 16-bit widths, including
wrapping edge cases and several documented-nowhere behaviours. It runs in about
15 ms, so unlike `sst65816` it is registered as an ordinary CTest and runs on
every build.

It does **not** test cycle counts, interrupt behaviour, or memory-mapped
registers. `sst65816` covers bus timing; nothing yet covers interrupts.

## Provenance

The tests themselves are from <https://github.com/gilyon/snes-tests> (MIT),
release `v1.4`, pinned by sha256 in the Makefile. `tests-full.inc` and
`tests_table.inc` are generated by upstream's `make_cpu_tests.py` and are not
committed — the built ROM is.

Only the harness here is ours: `main.asm`, `io.asm` and `flat.cfg` replace
upstream's SNES `main.asm` and `lorom.cfg`. The approach follows Daryl's
(8BIT's) port to the Kowalski simulator, posted at
<https://6502.org/forum/viewtopic.php?f=8&t=8119> — a flat memory map, an ASCII
character port in a separate `io.asm`, and no PPU, VRAM, vblank or joypad code.
That port could not be used directly: it is Kowalski assembler syntax with the
ca65 register-width directives stripped.

## Rebuilding

Needs `python3`, `cc65` (for `ca65`/`ld65`), `curl` and `unzip`. None of this is
needed to *run* the test — the ROM is committed, the same way `AllSuiteA.bin`
is.

```sh
make          # fetch upstream, generate, assemble, link over ../cputest816.bin
make clean    # drop generated files, keep the download
```

Always let the Makefile generate both `.inc` files. Upstream's release zip ships
`tests-full.inc`, `tests-basic.inc` and a single `tests_table.inc` — left over
from whichever variant was generated last — and pairing the full tests with the
basic table sends the test chain off the end of the table into `$0000`.

`tests-full.txt`, also generated, describes every test with its inputs and
expected outputs. It is what to read when a test number fails.

## Where this disagrees with SingleStepTests

Two behaviours this suite checks are ones `sst65816`'s reference models the
other way. Both were resolved in this suite's favour, against the datasheet;
the SingleStepTests cases covering them are expected to fail.

- **`(d,x)` pointer, emulation mode.** The second pointer byte is read with the
  increment wrapping inside the page the first byte came from, whatever DL is
  (`_DPX` in `w65c816s.h`). gilyon documents this as undocumented behaviour
  observed on hardware; SingleStepTests never wraps. Costs ~264 tests across
  `01.e 21.e 41.e 61.e 81.e a1.e c1.e e1.e`.
- **`JSR (a,x)` stack.** It is one of the eight instructions the datasheet's
  stack addressing section allows outside page 1 in emulation mode, so it uses
  `_SPW` like the rest. SingleStepTests keeps it confined. Costs ~43 tests in
  `fc.e`.

## Memory map

Upstream links a SNES LoROM cartridge; `cpuemu` has a flat 16 MB space, so the
segments are packed contiguously into one 160 KB image loaded at `$8000`. The
generator splits the tests across five code segments because `jsr` is
bank-local — a CPU constraint, not a LoROM one — each under 32K, so two fit in a
64K bank:

| Segment | Address | Bank |
|---|---|---|
| `CODE` (+`RODATA`, `TEST_DATA` at `$FFA0`, `VECTORS` at `$FFE0`) | `$008000..$00FFFF` | 0 |
| `BANK1` | `$010000..$017FFF` | 1 |
| `BANK2` | `$018000..$01FFFF` | 1 |
| `BANK3` | `$020000..$027FFF` | 2 |
| `BANK4` | `$028000..$02FFFF` | 2 |

`ld65` errors if a segment overflows, so that stays checked rather than assumed.
The tests scratch bank 0 pages 0-3, banks 6 and 7, and the `$00FFA0` pointer,
all clear of the image. `$7F00` holds the pass/fail byte and `$7F01` is the
character port.

## Running by hand

```sh
build/src/tests/cpuemu -a 8000 src/tests/cputest816.bin -o 7f01 -d 7f00 -b
```

`-b` is required: several tests execute `BRK`, which would otherwise stop
`cpuemu`. Unexpected BRK and COP still halt the run, because the harness plants
`STP` at the handler addresses.

The run prints one line per failing test and ends with either `Success` or
`Failed tests: $NNNN`, then halts on `STP`. `-d 7f00` dumps `FF` on success.
